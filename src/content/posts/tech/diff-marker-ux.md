## diff는 바뀐 곳만 보여 준다

이 도구는 VBScript에서 옮겨 온 화면 스크립트를 룰로 고치고, 결과를 원본과 나란히 diff로 보여 준다. 처음에는 색칠한 코드 위에 투명 textarea를 얹은 편집기를 직접 만들었다가 Monaco `DiffEditor`로 바꿨다. 룰이 줄을 끼워 넣어도 좌우 줄이 맞게 정렬되고, 표에서 "62번째 줄"을 누르면 그 자리로 스크롤되기 때문이다.

그런데 diff는 바뀐 곳만 보여 준다. 사람이 꼭 봐야 하는 자리는 diff에 나오지 않는 경우가 많았다. 룰이 일부러 바꾸지 않은 자리, 바꾸긴 했지만 맞는지 사람이 확인해야 하는 자리가 그렇다. 그래서 diff 위에 마커를 한 겹 더 얹었다.

## 마커 등급은 뜻으로 나눴다

마커 등급은 처음부터 색이 아닌 뜻으로 정의했다.

| 등급 | 뜻 |
|---|---|
| 확인 필요 (`check`) | 사람이 직접 보고 판단해야 한다 |
| 주의 (`warn`) | 바꾸지 않았고 위험할 수 있다 |
| 참고 (`info`) | 알아 두면 좋다 |

나중에 여러 줄에 걸친 흐름을 칠하는 `highlight`가 하나 더 생겼다. 밑줄 세 종류는 특정한 자리를 가리키고, 형광펜은 구간 전체를 가리킨다.

색은 diff가 쓰는 초록과 빨강을 피해 주황·보라·하늘·노랑으로 정했다. 처음에는 진한 호박색과 남색을 썼는데, 1px 밑줄로는 배경에 묻혀 잘 보이지 않았다. 마커가 겹치면 확인 필요가 맨 위에 오게 했다. 사람이 먼저 봐야 하는 쪽이다.

```tsx title="markers.ts"
type Level = "check" | "warn" | "info" | "highlight";

// 겹치면 위에 오는 순서. 형광펜은 맨 아래에 깔려야 밑줄이 보인다
const Z: Record<Level, number> = { highlight: 0, info: 1, warn: 2, check: 3 };

function toDecorations(markers: Marker[]) {
  return markers.map((m) => ({
    range: new monaco.Range(m.startLine, m.startColumn, m.endLine, m.endColumn),
    options: {
      inlineClassName: `marker marker-${m.level}`,
      hoverMessage: { value: m.message },
      zIndex: Z[m.level],
      // 스크롤 밖에 있는 마커도 오른쪽 눈금에서 위치가 보인다
      overviewRuler: { color: rulerColor(m.level), position: monaco.editor.OverviewRulerLane.Right },
    },
  }));
}
```

> [!TIP]
> 처음에는 밑줄이 하나도 그려지지 않았다. 데코레이션은 에디터가 아니라 모델에 붙는다. 결과를 바꿀 때 `setModel(null)`로 모델을 잠깐 떼는데, 그 순간 데코레이션이 모두 사라지고 남은 컬렉션에 `set()`을 불러도 다시 붙지 않는다. 모델을 다시 붙인 뒤 컬렉션을 새로 만들게 고쳤더니 0곳이던 밑줄이 32곳 그려졌다.

## 손대지 않은 `==`에 "완화했습니다"가 붙었다

문제는 엄격 비교 룰에서 생겼다. VBScript는 비교할 때 타입을 따지지 않는데, 옮겨 온 JS는 `===`를 쓴다. 그래서 화면에서 읽은 `"1"`과 숫자 `1`이 다르다고 나온다. 그렇다고 전부 `==`로 바꾸는 것도 위험하다. 룰은 이렇게 동작했다.

- 기본은 `===`를 그대로 두고 확인 필요 마커를 단다.
- 피연산자 이름이 `n`이나 `str`로 시작하면 타입을 짐작할 수 있다고 보고 `==`로 완화한다.

처음에는 완화한 `==` 자리에도 "완화했습니다" 마커를 달았다. 근거는 주석에 적힌 전제 하나였다. "1차 변환 코드는 `===`만 쓰므로 출력에 있는 `==`는 모두 이 룰이 바꾼 것이다."

이 전제가 틀렸다. 마커를 만드는 함수는 룰이 고친 AST를 받지 않는다. 엔진은 모든 룰을 적용한 뒤 출력 문자열을 한 번만 다시 파싱하고, 그 트리를 각 룰의 마커 함수에 넘긴다. 그래서 마커 함수는 방금 바꾼 `==`와 원래 있던 `==`를 구별할 수 없다. 게다가 옮길 대상 스크립트 중에는 이미 한 번 변환된 JS가 있었고, 거기에는 `==`가 원래 들어 있었다. 결국 화면이 손대지 않은 자리에 방금 바꿨다고 표시하고 있었다.

```ts title="convert.ts (원리만 다시 쓴 예시)"
for (const rule of rules) rule.apply(root, j);   // 여기서 연산자를 바꾼다
const output = root.toSource({ lineTerminator: "\n" });

// 마커는 출력을 새로 파싱한 나무에서 찾는다.
// 이 나무에는 "누가 바꿨는가"에 대한 정보가 없다
const outRoot = j(output);
const markers = rules.flatMap((r) => r.markers?.(outRoot, j) ?? []);
```

고친 방법은 단순하다. `==`와 `!=`에는 마커를 달지 않는다. 그래도 잃는 정보는 없다. 완화한 자리는 연산자가 바뀌었으니 diff에 이미 변경으로 잡힌다. 마커로만 알릴 수 있는 것은 바꾸지 않은 `===` 쪽이라서 그것만 남겼다.

```ts title="rule-strict-equality.ts"
markers(root, j) {
  const out: Marker[] = [];
  root.find(j.BinaryExpression).forEach((p) => {
    const op = p.node.operator;
    // ==, != 는 이 룰이 바꾼 것인지 원래 그랬던 것인지 여기서는 모른다.
    // 바꾼 자리는 diff가 보여 준다
    if (op !== "===" && op !== "!==") return;
    const mk = marker(p.node, STRICT_MESSAGE, "check");
    if (mk) out.push(mk);
  });
  return out;
}
```

> [!WARNING]
> 마커 함수가 무엇을 받는지부터 확인해야 한다. 출력을 다시 파싱한 트리를 받는다면 그 함수는 "지금 이런 모양이다"까지만 말할 수 있고, "내가 이렇게 바꿨다"는 말할 수 없다.

이 일 이후로 마커에는 diff가 보여 주지 못하는 것만 담기로 했다. 바뀐 자리를 마커로 한 번 더 표시하면 신호가 겹치고, 이번처럼 틀린 신호가 섞일 가능성만 커진다.

## 덩어리 단위 되돌리기는 하루 만에 껐다

Monaco를 들이면서 근거로 든 것 중 하나가 변경 덩어리마다 붙는 되돌리기 화살표였다. 덩어리 하나를 누르면 그 부분만 원본으로 돌아간다. 그런데 바로 다음 날 이 기능을 껐다.

한 덩어리에 여러 룰의 변경이 겹쳐 있으면 그중 한 룰만 빼는 것이 불가능했다. 되돌린 뒤에는 무엇이 빠졌는지도 남지 않았다. 사람들이 원한 것은 룰 단위로 되돌리는 것이었다.

그래서 룰 패널의 체크로 바꿨다. 체크를 끄면 그 룰만 빼고 다시 변환한다. 서버 변환이 결정적이라서 쓸 수 있는 방법이다. 입력과 룰 목록이 같으면 결과도 항상 같다.

```ts title="diff-options.ts"
export const DIFF_OPTIONS = {
  originalEditable: false,        // 원본은 기본 잠금
  renderMarginRevertIcon: false,  // 덩어리 단위 되돌리기 화살표를 끈다
  renderGutterMenu: false,        // 가운데 손잡이도 같은 이유로 끈다. 설정에서 켤 수 있다
};
```

두 편집기 사이에서 덩어리를 통째로 옮기는 손잡이(gutter menu)도 같은 이유로 기본값을 껐다. 다만 이건 설정에서 켤 수 있게 남겼다. 덩어리째 옮기는 편이 빠른 사람도 있으니 그 선택까지 막을 생각은 없었다.

## 정리

- 마커 등급은 뜻으로 정했다. 확인 필요·주의·참고에 형광펜을 더했고, 색은 diff의 초록·빨강과 겹치지 않게 골랐다.
- Monaco 데코레이션은 모델에 붙는다. 모델을 갈아 끼웠으면 데코레이션도 다시 만들어야 한다.
- 마커 함수가 출력을 다시 파싱한 트리를 받으면 룰이 바꾼 것과 원래 있던 것을 구별할 수 없다. 이를 놓치고 "완화했습니다"를 달았다가 손대지 않은 자리에 잘못된 표시가 붙었다.
- diff가 이미 보여 주는 변경은 마커로 다시 표시하지 않는다. 마커는 바뀌지 않았지만 위험한 자리에 쓴다.
- 덩어리 단위 되돌리기는 룰 단위로 판단하는 흐름과 맞지 않았다. 룰 체크를 끄고 다시 변환하는 방식으로 바꿨다.
