노코드 UI 빌더는 화면을 JSON 파일로 저장한다. 위젯 트리, 속성, 데이터셋 정의가 들어 있다. 위젯 구조를 바꿀 때마다 이미 저장된 파일이 새 코드와 맞지 않는 문제가 생겼다. 이전 글의 슬롯 재설계 때 파일에 버전 필드를 넣었고, 그 뒤로 이 필드가 계속 쓰였다.

이 글은 마이그레이션 구조, 파일을 열 때의 처리 방식, 쌓인 단계를 정리한 방법을 다룬다. 작업은 AI 코딩 에이전트와 함께 했고, 일부 단계는 동료가 추가했다.

## 버전 필드와 단계 배열

파일 최상위에 `version`을 둔다. 필드가 없으면 0(레거시)으로 본다. 처음에는 단순한 함수 배열이었고, 배열 인덱스가 시작 버전이었다. 현재 버전 상수도 손으로 올렸다. 단계 설명은 IDE 쪽에 따로 하드코딩했다.

2주쯤 뒤 객체 배열로 바꿨다. 설명이 변환 코드와 떨어져 있으면 둘 중 하나만 고치는 일이 생기기 때문이다.

```ts title="screen-migrations.ts"
export type Migration = {
  from: number;
  to: number;           // from + 1. 건너뛰는 단계는 지원하지 않는다
  description: string;  // 확인 UI에 그대로 보여 줄 안내 문구
  migrate: (json: any) => any;
};

const MIGRATIONS: Migration[] = [
  { from: 0, to: 1, description: '버전 식별자 추가. 구조 변경 없음.', migrate: (j) => ({ ...j, version: 1 }) },
  // 새 단계는 여기에 push만 한다
];

// 현재 버전은 배열에서 계산한다. 상수를 따로 올리지 않는다
export const CURRENT_VERSION = Math.max(0, ...MIGRATIONS.map((m) => m.to));

export function stepsFrom(version: number): Migration[] {
  return MIGRATIONS.filter((m) => m.from >= version).sort((a, b) => a.from - b.from);
}

export function migrateScreen(json: any) {
  const v: number = json?.version ?? 0;
  if (v === CURRENT_VERSION) return json;
  if (v > CURRENT_VERSION) {
    console.warn(`파일 버전(${v})이 지원 버전(${CURRENT_VERSION})보다 높다. 그대로 연다.`);
    return json;
  }
  let out = json;
  for (const step of stepsFrom(v)) out = step.migrate(out);
  // 어떤 단계가 version을 빠뜨려도 마지막에 맞춘다
  return out.version === CURRENT_VERSION ? out : { ...out, version: CURRENT_VERSION };
}
```

`from` 기준 정렬은 실제로 필요했다. 한 번은 v7→v8 단계가 배열에서 v6→v7보다 먼저 들어갔다. 배열 순서대로 돌렸다면 두 단계가 뒤바뀐 순서로 실행됐을 것이다.

새 단계 추가 절차는 "배열에 객체 하나 넣기"가 전부다. 현재 버전과 UI 안내가 같이 따라온다.

## 열 때 자동으로 바꾸지 않았다

처음에는 파일을 읽은 직후 마이그레이션을 바로 적용했다. 화면은 최신 형식으로 떴다. 문제는 저장이었다. 메모리는 최신 버전인데 파일은 사용자가 저장하기 전까지 옛 버전이다. 화면에 보이는 상태와 파일의 버전이 사용자가 모르는 사이에 어긋난다.

그래서 결정을 사용자에게 넘겼다.

- 파일 로더는 원본 JSON과 함께 `fileVersion`, `needsMigration`을 돌려준다. 변환은 하지 않는다.
- 패널은 확인 화면을 보여 준다. 각 단계의 `from → to`와 설명이 나온다.
- 적용하면 변환한 내용으로 편집기를 띄우고 "저장 안 됨" 표시를 켠다. 실제 반영은 사용자가 저장했을 때만 일어난다.
- 거부하면 안내 화면을 띄운다. 다시 열면 또 묻는다.

> [!NOTE]
> 코드에서 JSON을 직접 넣는 API의 자동 변환은 그대로 뒀다. 호출한 쪽이 의도를 명시했기 때문이다. 묻는 건 사람이 파일을 열 때뿐이다.

처음에는 전역 확인 대화상자로 물었다. 탭을 여러 개 동시에 열면 어떤 파일의 질문인지 알기 어려웠다. 그래서 각 패널 안에 직접 표시하도록 바꿨다.

### 읽기 전용 모드

"변환은 하기 싫은데 내용은 보고 싶다"는 경우가 있었다. 안내 화면에 읽기 전용 보기를 추가했다.

- 캔버스만 상호작용할 수 있고, 툴바, 아웃라이너, 인스펙터, 하단 패널은 HTML `inert` 속성으로 막았다. 포인터, 키보드 포커스, 텍스트 선택, 접근성 트리가 한 번에 막힌다.
- 캔버스에서는 클릭으로 위젯 하나를 선택하는 것만 허용했다. 다중 선택, 드래그, 리사이즈는 capture 단계에서 막았다.
- 저장 단축키는 토스트로 안내하고 막았다.
- 상단 배너에서 바로 적용으로 넘어갈 수 있다. 이때 편집기를 강제로 다시 마운트해서 메모리 상태를 버리고 새로 변환한다.

## v8까지 쌓인 단계를 v1로 정리했다

한 달 반 동안 단계가 v8까지 늘었다. 버전 식별자를 넣은 v1 다음으로 루트 노드 표시, 중복 ID 정리, 탭 슬롯 ID를 인덱스에서 고정 ID로 바꾸기, 입력 위젯 속성 키 이전, 루트 컨테이너 도입, 위젯 앵커 기본값, 루트 컨테이너 제거였다. 루트 컨테이너는 도입하고 이틀 뒤 반대 방향 단계로 다시 걷어 냈다.

단계마다 오래된 구조를 이해하는 코드가 남았다. 새 단계를 쓸 때 앞 단계들의 결과를 머릿속에 그려야 했다. 그런데 저장된 화면 파일은 아홉 개뿐이었다.

그래서 아홉 개 파일을 모두 v8까지 올린 다음, 결과의 버전을 1로 다시 썼다. 배열에는 v0→v1만 남기고 v2~v8 코드는 지웠다. 주석에는 각 단계를 한 줄씩 요약하고, 코드를 복원할 수 있는 커밋을 적어 뒀다. 앞으로의 새 단계는 v2부터 시작한다.

> [!TIP]
> 마이그레이션 코드를 영원히 들고 갈 필요는 없다. 대상 파일을 전부 알고 있고 한 번에 올릴 수 있다면 기준점을 새로 잡는 편이 낫다. 지운 코드는 git 이력에 남는다.

## 정리

- 파일에 버전 필드를 두고, 없으면 0으로 본다.
- 단계는 `{from, to, description, migrate}` 객체 배열이다. 현재 버전은 배열에서 계산하고, 적용 순서는 `from`으로 정렬한다.
- 사람이 파일을 열 때는 자동 변환하지 않고 확인을 받는다. 반영은 저장했을 때만 한다.
- 변환을 원하지 않는 경우를 위해 `inert`와 capture 단계 차단으로 읽기 전용 보기를 만들었다.
- 대상 파일이 적고 모두 알 수 있을 때, 최신까지 올린 뒤 v1로 기준점을 다시 잡았다.
